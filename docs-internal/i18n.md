# Documentation in two languages

English is authoritative. Chinese is a translation that must not silently rot.

## Convention

- One directory tree, two languages, distinguished by a **BCP 47 suffix**: `README.md` / `README.zh-CN.md`,
  `docs/operations.md` / `docs/operations.zh-CN.md`. Not `docs/zh/` — a mirrored tree drifts worse,
  because a file added on one side has no obvious counterpart to check against on the other.
- The English file is the source of truth. A translation never carries information the English file lacks:
  if a Chinese page needs to say more, the English page should say it first.
- Code blocks, commands, identifiers, file paths and config keys are **not translated**.

## Two suffixes, and why

The repository pairs on `.zh-CN.md`; the published site pairs on `.zh.md`. That is not an oversight, it is a
constraint of the site builder: mkdocs-material ships `partials/languages/zh.html` and no `zh-CN` variant, and
a locale of `zh-CN` fails the docs build at template time with `TemplateNotFound`. The site therefore uses
`locale: zh` and the `.zh.md` suffix, while `scripts/check-i18n.sh` — which only knows about file names, not
locales — accepts both suffixes.

A consequence worth knowing: a page can be translated for the site and still be missing a repository pair, or
the other way round. `README.zh-CN.md` and `examples/local-quickstart/README.zh-CN.md` are repository-only (the
site links to them on GitHub); the pages under `docs/` that have a Chinese version use `.zh.md` and are built
into `/zh/`.

## Avoiding stale translations without spending tokens

Three options were considered:

| option | verdict |
|---|---|
| gettext/PO pipeline (`mdbook-i18n-helpers`, `sphinx-intl`) | rejected: it is the right tool for a *book*, and this documentation has no build step. It would add a Rust toolchain and a `.po` lifecycle to translate twelve markdown files |
| external translation-drift services (Polylens, Fiberplane's `drift`) | rejected: a hosted service for a repository whose CI has no runner yet |
| **source digest + CI check** | **adopted** — no toolchain, no service, and it answers the only question that matters: *is this translation older than the text it claims to translate?* |

`scripts/check-i18n.sh` keeps `docs/.i18n.json`, a map of translation → the digest of the English file it
was made from:

```sh
scripts/check-i18n.sh --update   # after translating: record the current source digest
scripts/check-i18n.sh            # CI: report drift, and list English docs with no translation
```

Exit codes: `0` nothing stale, `1` a translation is older than its source (fails CI), `2` the manifest is
missing or unreadable (never "pass because it could not check").

## What is translated today

| page | state |
|---|---|
| `README.md` → `README.zh-CN.md` | current |
| `docs/index.md` → `docs/index.zh.md` | current — and the only page whose Chinese version is the site's `/zh/` landing page |
| `docs/documentation-index.md` → `docs/documentation-index.zh.md` | current |
| `docs/getting-started/quickstart.md`, `docs/getting-started/kubernetes.md`, `docs/limits.md`, `docs/handbook/architecture.md`, `docs/why-not-a-jump-host.md` → `*.zh.md` | current; built into `/zh/` |
| `docs/handbook/backends.md`, `docs/handbook/operations.md`, `docs/handbook/troubleshooting.md`, `docs/release.md` | **English only** — served in English under `/zh/` (the site falls back rather than 404s) and listed as missing by the checker |
| `examples/local-quickstart/README.md` → `README.zh-CN.md` | current |
| `examples/{static-endpoints,pod-image,kubernetes-sandbox,docker-sandbox}/README.md` | English only |
| `docs/adr/*`, `docs/acceptance/*` | English only on purpose: a decision record and an acceptance log are evidence, and a translated quote is not evidence |

Which pages get a Chinese version is a judgement about what a Chinese reader opens first, not an aspiration to
translate everything: a translation that nobody maintains is worse than an honest fallback to English.
Translating the remaining handbook pages is the next increment; the checker makes "not yet" visible without
blocking the release.

## On the site

`mkdocs.yml` configures `mkdocs-static-i18n` in `suffix` mode with `locale: zh` and `fallback_to_default: true`,
so `/zh/` carries the pages above in Chinese and everything else in English. Navigation labels are translated
through `nav_translations`, and the language switcher in the header is generated by the plugin — the
`**English** · **中文**` line at the top of a page is a label, not a link, and does not need to be maintained
by hand.
