# Acceptance record — 2026-11-17 (M0–M3)

Evidence for the milestones that were verified before the cluster run. Each block is a command that was
actually executed against the running code; the outputs are trimmed to the decisive lines.

```

 "error":"... identities[0]: fingerprint \"SHA256:<base64-body>\" is not base64: illegal base64 ..."}

A fully specified config is accepted instead:

```

namespace/template/image/user/key, out-of-range port, unknown host key policy, duplicate backend name,
duplicate fingerprint (after normalising `SHA256:` and padding), bad endpoint, wrong duration.

## M3 — adoption and observability

Cluster run, gateway restarted with one live lease:

```
{"level":"INFO","msg":"adopted existing leases","count":1}

$ curl -s localhost:8099/metrics | grep -E '^keypod_'
keypod_leases_adopted 1
keypod_leases_idle 1
keypod_pool_warm{backend="sandbox"} 2

claims after restart: 3   (2 warm + 1 leased; no orphans)
```

Before the fix that this test forced, the same restart produced `adopted=0`, a **new** instance for the
same identity, and 6 claims (2 more per restart). That defect is recorded in
`2026-11-17-m4.md` §Bugs 2–3.
